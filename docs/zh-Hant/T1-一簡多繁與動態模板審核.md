## 動態句與屬性

1. 按完整 English 句子、現 zh-CN 語義與實際呼叫參數共同審核。參數名稱及使用者值不能簡繁轉換，不能用英文片段拼句。
2. 不得新增未知參數或刪去有意義的動態內容。中英文參數集合不一定逐項完全相同：如中文不需要英文的單複數單位 {unit}，應逐句判斷，不能為了機械一致而改壞句子。
3. English 的 one／other 保留，繁體數量句按自然中文編寫；缺少或無效翻譯直接回到 English，不經 zh-CN。
4. title、placeholder、aria-label、data-placeholder、模板文字和原生選單都屬於審核範圍。快捷鍵、URL、技術錯誤細節、原文版本名原樣保留。
5. 文字與插值仍由現有安全文字綁定處理，不把參數當 HTML 執行；不改可編輯內容或輸入值。
6. 中文全角標點延續既有語境，不強制地區出版引號；不轉換 Greek／Hebrew 字元、RTL 或經文標點。

## 需優先確認的方向問題：s.S0622

English：`Replace the current {newTranslation} column (including any edits) with {oldTranslation}? Ctrl+Z undoes this.`

呼叫點 [ui-menus.js](../../js/utils/ui-menus.js) 中，`newTranslation` 接目前欄的 `DA_STATE.parallelLabel`，`oldTranslation` 接新選的 `code`。因此英文語義正確，而現 zh-CN 的「用 {newTranslation} 替換目前 {oldTranslation}」方向相反。這是既有提示文案問題，不是替換功能錯誤。

建議繁體完整句：

> 確定以 {oldTranslation} 取代目前的 {newTranslation} 欄（包含所有編輯內容）？可按 Ctrl+Z 復原。

T1 僅登記，沒有修改來源。T2 應為繁體新增方向斷言，例如目前 ESV、新選 NASB 時，提示須表示以 NASB 取代 ESV。是否同時修正 zh-CN 句子另待人工批准；不更名參數、不改業務流程，也不回改凍結分支。
