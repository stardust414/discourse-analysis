# 残留英文审计

阶段：5（v1.1 批准后的当前状态）。日期：2026-11-03。上游基线：Discourse Analysis 3.3.1 / `98da0241c38eef936be0f06cf736aa607dda0b62`。

**结论：本轮识别的应用可控、适合中文化的普通 UI 遗漏为 0。** 保留英文有明确用途：品牌和名称、双语专业信息、稳定数据、技术详情、系统控件，关系缩写等学习对照信息。没有把“屏幕上没有任何英文”作为完成标准。

## 审计怎样进行

重新扫描了 37 个应用源码文件，涵盖 HTML、CSS、所有非 vendor 渲染模块、Electron main/preload、新增原生菜单适配及 API 代理。除阶段 2 清单外，还检查了阶段 3 新增文案、动态模板、提示属性、错误边界、CSS 生成文字和默认桌面菜单。

原始文本审计快照保留 2,397 个按文件、类型和文本去重的记录及出现次数。它既包括界面文字，也包括选择器、协议值、数据和诊断，**不是 2,397 条待翻译 UI**。快照的粗分类用于维护提醒；本报告的语义分类、470 条追踪映射和运行检查共同解释保留原因。

工具 `node scripts/audit-i18n.cjs` 核对翻译键，并提醒新增或增多的源码文本。该检查已纳入 unit tests。当前有 600 个英文键、600 个中文键，没有故意缺少中文值的生产键；434 个显式引用键检查通过，动态关系键另由五套 profile 矩阵验证。

另在浏览器及真实 Mac arm64 包中查看主界面、欢迎页、设置、五套指南、关系选择器、评论、平行栏、上下文菜单和导出菜单。原生菜单的中英文标签、角色及快捷键也已导出核对。截图和日志见 [阶段 5 验证证据](阶段5验证证据/)。

## 1. 品牌／产品名

Discourse Analysis、Logos、Accordance 以及页脚来源名称保留。产品名出现在窗口标题、页首、欢迎语、PDF 元数据和原生应用菜单中；周围操作文字已翻译。C01 方法名称“篇章分析”的批准不意味着软件品牌必须改名。

## 2. profile 名

Josiah、BibleArc、Gurtner、Beale、Schreiner 保留。用户自定义方案名及原版自动创建的原始名称 Custom 保留；Custom 后的界面说明改为“（自定义）”。高级记号编辑器中的原始英文关系名称是可编辑数据，不填入双语译名。其 tooltip／ARIA 及选择器、指南提供中文显示。

## 3. Bible translation 名

ESV、English Standard Version、NASB (1995)、Chinese Union、Reina-Valera、Luther 等正式名称和年份保留；平行译本列表的语言和简繁说明已接入中文。译本代码、请求参数及实际经文不变。

阶段 2 的 S0603、S0605 归入保留名称；不是漏译。

## 4. Bible／Greek／Hebrew 缩写

SBLGNT、LXX、WLC、NT、OT 等版本或来源缩写保留。显示说明“希腊文”“希伯来文”“旧约”“新约”等按已有文案翻译。John、Romans、Phil 等经文输入例子继续采用现有解析器认识的写法；没有顺带增加中文书卷识别或改经文引用数据。

## 5. API／技术名称

API.Bible、Bolls、Firebase、HTTP、JSON、PNG、PDF、LZString、URL 和文件扩展名保留。应用自己的错误说明已翻译，原始服务错误详情、状态码、文件名和链接作为纯文字保留。例如中文“同步失败：”后面可能出现第三方英文技术详情。

S0043、S0045 是 main／API 代理内部的技术错误，保留英文证据；渲染层的提示已中文化。没有将 API key、URL、项目代码、字段名或嵌入数据当作翻译对象。

## 6. 快捷键

Ctrl、Cmd、Enter、Tab、Backspace、Esc、字母键、快捷键组合和 `aria-keyshortcuts` 保持实际键位。快捷键用途、帮助说明和 tooltip 已翻译。原生菜单的角色与快捷键保持原版，只有标签随界面语言切换。

## 7. 用户内容

经文、评论、回复、主旨摘要、项目标题、姓名、自定义名称及平行经文原样保留，包括用户恰好输入的英文。不会因为内容等于某条内置英文而自动翻译。

S0028 Imported text、S0154 Imported bracket、S0349 added verses 会进入项目内容或经文范围，保持原默认数据语义；S0124 Custom 也是原始方案数据名称。只翻译明确分开的显示说明，不迁移旧项目。原版保存的 Anonymous 等署名同样不因字面相同而替换；真正缺少署名的界面回退可以显示中文。

## 8. 专业术语故意保留的 English

审定关系全称采用“中文 + English”，包括理由 Ground、双向支持 Bilateral、双侧理由 Double Ground、意思—解释 Idea-Explanation、方式关系 Way-End、手段—目的 Means-End、逆接 Adversative 等。五套 profile 的不同英文名称分别处理。

关系指南与悬停帮助的关键词显示中文，并保留对应英文连接词，便于对照与搜索。图内 Ac/Pur、G、∴、?、星号和其他缩写／符号不翻译。高级编辑器的可写原名保持数据原值。

## 9. 尚未批准而 fallback English

**当前故意 fallback 条目：0。** C13–C17 已在阶段 5 正式批准并接入：

| 原文 | 当前中文 |
| --- | --- |
| COORDINATE RELATIONSHIPS | 并列关系 |
| SUBORDINATE RELATIONSHIPS | 从属关系 |
| Support by Restatement | 以重述支持 |
| Support by Distinct Statement | 以不同陈述支持 |
| Support by Contrary Statement | 以相反陈述支持 |

英文分组原词仍可在 tooltip 学习对照，这属于有意保留英文信息，不是缺失翻译。紧凑关系按钮默认使用中文 + 当前 profile 原始简称，空间极紧时可只显示简称；其完整双语无障碍名称、tooltip 和详情仍可查。没有为保持中文而隐藏、改写或截断英文简称。

其他未点名 C 条目的历史审核状态不因此提升。阶段 4 已确认批准的两个云同步开关继续使用中文。回退能力仍保留，测试通过临时模拟缺失字典来验证，不在产品中故意制造缺项。

## 10. macOS／Electron 原生系统文字

应用接管了原有 Electron 菜单的标签翻译，保留原菜单结构和动作，不再把 File、Edit、View 等可控菜单统称为“无法翻译”。实际包中已验证 English 与中文即时切换。

文件选择器、原生确认框标准按钮、Services 的系统子项目、About 的系统元数据及系统自动附加窗口项目，可能继续使用系统／Electron 的语言。它们不属于 DOM 字典，也未通过更改 macOS 语言设置或升级 Electron 来处理。没有改变系统安全策略或签名。

## 11. 开发日志

console 中的启动、网络、解析、文件及云服务诊断仍可为英文。全局可见错误的外层消息已中文化，并保留原技术详情。只写入开发日志、程序判断或协议的字符串不列为 UI 漏译。

缺失翻译的最终防护文字 `Text unavailable` 保留为英文安全回退；已识别的正常 UI 路径没有未知键。新增键校验、占位符检查和完整测试用于避免用户走到这个保护分支。

## 12. 确实遗漏的 UI 文案

**本轮已识别的应用可控普通 UI 遗漏：0。** 没有尚待补译的 A 类条目。不能把系统／第三方内容、用户数据、品牌和双语专业信息计为漏译，也不宣称静态工具能证明未来所有运行分支没有任何问题。

470 条来源记录全部有处置：462 条接入显示翻译，4 条保留原始数据，2 条保留技术详情，2 条保留译本名称。逐条英文、来源位置、翻译键和理由见 [阶段 4 覆盖映射](阶段4覆盖映射.json)；新增源码变化由 [源码文本审计快照](阶段5源码文本审计.json) 跟踪。


## 阶段 5 的额外核对

选择器的英文全称从紧凑按钮移到完整的 tooltip／ARIA／hover／focus 详情，图内记号未变。资料教学用缩写按原始 abbr 保留大小写、空格、斜线和星号，例如 BL、DG、* / G、Ac / Pur*、W / Ed*，不照示例改成统一写法。

来源 S0031 的原英文“Double-click to split…”在实际程序中不成立。阶段 5 同步修正中英文为在光标处按 Enter 拆分；这是一项经授权的上游 UI 文案修正，原始提取记录保留作证据，拆分功能不改。

平行栏 S0617 增补“每节经文只载入到首行，续行初始为空”的说明，对应原版既有分配规则；没有修改平行栏业务行为。

原版词内合并补空格、Developer ID 签名限制及系统原生／第三方语言边界不变。当前没有识别到需要补译的普通 UI；英文对照、用户内容、数据、品牌和开发诊断继续按上述类别保留。
