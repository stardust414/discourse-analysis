# 维护与上游同步

当前版本基于 Discourse Analysis 3.3.1、上游 `98da0241c38eef936be0f06cf736aa607dda0b62`，分支 `codex/zh-cn-i18n`。阶段 6 冻结应用实现；内部版本仍为 3.3.1。冻结记录与最终包的源码对应关系见[最终验证报告](最终验证报告.md)。未知新版的同步必须在新分支验证，不能直接覆盖已验证交付。

## i18n 架构和边界

原生 HTML／CSS／经典 JavaScript 脚本，没有新增大型框架或运行时依赖。

| 文件／机制 | 职责 |
| --- | --- |
| `js/i18n/en.js` | 完整英文基准字典；新增 UI 必须先有英文 key |
| `js/i18n/zh-CN.js` | 简体中文显示字典，不进入业务数据 |
| `js/i18n/i18n.js` | locale、插值、英文 fallback、显式 DOM 绑定、即时刷新、本机偏好 |
| `js/i18n/relationships.js` | 专业名称、帮助、搜索的独立显示层；识别未改名的内置关系 |
| `js/i18n/native-menu.cjs` | 原 Electron 菜单标签；保留 role、动作和快捷键 |
| `data-i18n` 系列 | 明确标记静态文本和 title／placeholder／ARIA／CSS 提示属性 |
| `DA_I18N.t`、`bindText`、`bindValue` | 动态完整句、模板和随语言变化的派生显示 |

`biblebracket_language` 仅在本机存储 `system`、`en`、`zh-CN`。Follow System 使用首选系统 locale；Hans／CN／SG／MY 和裸 zh 选简体，Hant 与未支持语言回退英文。不要将此字段写入项目、云端数据或 undo／redo。

译文不替换用户输入，不写 innerHTML，不对整个 DOM 作英文全文替换。语言切换应保留节点、输入焦点、草稿及选区。模板 clone 和动态新增节点也要应用当前语言。更详细的 API 说明见[开发 i18n 文档](../i18n.md)。

## 新增界面文字

每次新增 UI 字符串都需要：

1. 在 `en.js` 添加语义完整的英文 key。不要拼接 `Loaded ` + count + ` propositions` 这样的碎片。
2. 在 `zh-CN.js` 添加自然中文；专业词先查人工批准规范，未批准时记录并明确回退，不自行发明译名。
3. 标记所需 text、title、placeholder、aria-label、data-placeholder；带图标按钮优先给文字独立 span，避免破坏 SVG／快捷键结构。
4. 对动态句使用变量模板，如 `DA_I18N.t('passage.loaded', { count })`；以 textContent 等安全文字渠道呈现，技术详情原样作为变量，不执行为 HTML。数量表达按英文 plural 结构处理。
5. 运行 audit，人工审查新字符串分类，然后运行相关与完整测试。需要时在真实桌面包中打开该状态。

不要翻译经文、评论、摘要、姓名、项目标题、自定义名称、字段名、IDs、URL、API key、译本 code、图内记号、星号或稳定嵌入数据。

## 专业术语和紧凑显示

权威材料：[中文界面翻译规范 v1.1](中文界面翻译规范-v1.1.md)、[专业术语审核表 v1.1](专业术语审核表-v1.1.md)、[本次批准决定](阶段5人工审核决定-v1.1.md)。v1.0 的既有批准继续有效，历史未逐项批准的通用词条不自动提升状态。

不得随意改关系译名、relationship ID、profile ID、映射、主次、缩写、符号、星号、颜色或顺序。不同方案的英文名称分别处理，不能把近义词合并为一个内部术语。用户改名及自定义方案原样显示。

`selectorPresentation(type)` 只返回显示值。紧凑按钮默认中文 + 当前 `DA_PROFILES.getAbbr(type)` 原值，先压缩中文，极窄时只显示简称。保留完整大小写、空格、斜线及星号，不截断简称；完整双语信息在 Guide／tooltip／hover／focus／ARIA 中可查。不要把该显示对象写回 profile。

## 自动检查能做什么

```sh
npm run check
npm run test:e2e
node scripts/audit-i18n.cjs
```

`check` 含 lint、typecheck 和全部 unit。最终基准为 343 unit、107 E2E，原有英文断言不得减少。Playwright 需要与当前锁定版本匹配的已有浏览器；本机沿用阶段 2.5 的目录：

```sh
PLAYWRIGHT_BROWSERS_PATH="$PWD/scratch/phase25/browsers" npm run test:e2e
```

该缓存不分发。如果换机器，应由维护者明确安排匹配浏览器环境，不要为消除启动错误而升级项目依赖或修改测试断言。

audit 检查字典键、英文基准、中文覆盖、插值和显式绑定，并对新增／增加的源码文本作提醒；unit 也包含该守卫。当前快照为 `阶段5源码文本审计.json`，470 条阶段 2 来源处置记录仍在 `阶段4覆盖映射.json`。它们统计口径不同，源码记录不是待翻译 UI 数量。

audit **不能**自动判断字符串语义、译文质量、所有动态运行路径、布局、系统原生文字或经文内容是否正确。看到提醒后，必须人工区分：UI、用户数据、内部字段、技术日志、品牌／名称、专业术语；查明应翻译、应保留或待批准的原因。只有审查完成并更新残留英文说明、翻译键及测试后，才可以运行 `--write-snapshot` 登记新的已审查状态。不能直接更新快照消除失败。

## 同步未来上游版本

先备份自己的项目文件，保留已验证分支、ZIP 和校验值。以下是未来的操作方法，本阶段没有实际同步未知新版。

1. 确认工作区干净，查看 `git remote -v`。当前 `origin` 指向原作者仓库；若要使用 `upstream` 别名，先确认未存在同名远程，再执行 `git remote add upstream https://github.com/josiahhoi/discourse-analysis.git`。不要改写现有远程地址。
2. `git fetch upstream --tags`，只下载记录；查看上游版本、提交及发行说明。记录准确的新 commit，不把移动的 main 名称当作永久验证基线。
3. 从已验证的本地化提交建立新分支，例如 `git switch -c codex/zh-cn-sync-<版本> <已验证提交>`。不要直接在最终交付分支上合并未知版本。
4. 查看新旧上游之间的日志和 diff。选择 merge 或 rebase；需要保留既有验证历史时优先 merge 到新同步分支。若不熟悉 rebase，不要对已共享分支重写历史。
5. 处理冲突，逐项检查 i18n 标记、动态句、菜单、项目数据边界和五套 profile。上游若改变 schema 或 IDs，先设计兼容和迁移方案并取得批准，不用翻译层擅自修补。
6. 重新扫描新增英文 UI，更新 en／zh-CN；专业词按审核流程处理，不把新关系直接归并到旧关系。
7. 运行 audit，解释每个新增源码文本，并审查残留英文分类；通过后再登记快照。
8. 运行全部 unit／E2E，保留 English 模式原断言，再检查中文搜索、缩写、五套方案和数据兼容。测试减少要说明原因并审核，不能用降低覆盖解决失败。
9. 使用目标上游明确的依赖环境构建 Mac arm64。若上游要求升级组件，应另开经批准的升级工作，不能混入一个“仅翻译”补丁。
10. 从实际 ZIP 解压做桌面 smoke：首次启动、三种语言、真实经文、Enter、关系、五套方案、指南、评论／摘要、双栏、JSON／PNG／PDF 恢复、重启。UI 有变化时重做窗口／缩放／Light／Dark 矩阵。
11. 记录新旧上游 commit、已验证本地化 commit、测试结果、签名状态、包 SHA-256 和已知限制，经人工确认后才替换交付。不自动推送、发布或提交 PR。

## 重建本次冻结版本

当前机器使用现有已锁定依赖，不重新安装。内部版本和 lockfile 不修改：

```sh
npm run build:mac -- --config.directories.output=dist/phase6-build
mkdir -p dist/final-zh-CN
cp 'dist/phase6-build/Discourse Analysis-3.3.1-arm64-mac.zip' \
   'dist/final-zh-CN/Discourse Analysis-3.3.1-zh-CN-arm64-mac.zip'
shasum -a 256 'dist/final-zh-CN/Discourse Analysis-3.3.1-zh-CN-arm64-mac.zip'
```

重建前若目录中已有交付，使用新的输出目录，不覆盖已验证文件。重新构建的 ZIP 可能因打包时间等元数据得到不同哈希；必须重新记录并从新 ZIP 验证，不能沿用旧哈希。当前正式交付以最终报告列出的文件和 SHA-256 为准。

交付核验包含 ZIP CRC、arm64 Mach-O、应用版本、isPackaged、包内源码与冻结提交逐字节一致、完整包清单、无 scratch／tests／个人资料、原版权／来源保留及原版项目兼容。测试 userData、浏览器缓存和导出测试文件只放隔离 scratch，不放应用 ZIP。
