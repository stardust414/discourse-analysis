https://github.com/josiahhoi/discourse-analysis

目标是为最新版 Discourse Analysis 增加正式、可维护的简体中文界面，并保留英文界面，最终在我的 Apple Silicon Mac 上构建可运行的 arm64 macOS 桌面应用。

## 一、总体目标

不要做简单的“把英文字符串硬编码替换成中文”。

我要的是一个正式、可维护的国际化方案：

- English
- 简体中文
- 如实现成本合理，支持“跟随系统”
- 用户选择的语言能够被记住
- 不破坏现有项目文件兼容性
- 不破坏现有 BibleArc / Gurtner / Beale / Schreiner / Josiah 等 notation profile
- 不修改经文本身的数据内容
- 后续上游项目升级时，尽量容易同步
- 最终代码质量应达到可以考虑向原作者提交 PR 的程度

请优先采用最小侵入、易维护的架构。

## 二、非常重要的工作方式

整个项目必须分阶段进行。

不要一次性把所有事情做完。

每个阶段完成后，先停下来向我提交“阶段报告”。

阶段报告必须使用非技术人员可以理解的中文，避免堆砌代码术语。

每份报告都使用这个结构：

1. 这一阶段做了什么
2. 发现了什么
3. 有没有风险或需要注意的问题
4. 有没有需要我决定的事情
5. 下一阶段准备做什么
6. 当前是否建议继续

如果必须提到技术术语，请顺便用一句白话解释。

不要只告诉我“修改了哪些文件”，而要告诉我这些修改对软件意味着什么。

除非涉及我必须作出的产品、翻译或术语选择，否则技术决策请你自己判断，不要把普通工程问题丢给我。

# 阶段 2：建立中文翻译规范与术语表

这是整个项目中最需要人工审核的一阶段。

这一阶段仍然不要开始大规模替换界面。

请先从源码中提取、整理所有用户可见文本，并将它们分成以下几类：

A. 普通界面词汇
例如：
Save
Open
Export
Settings
Cancel
Delete
Comments
Help

B. 操作与状态文本
例如：
Passage loaded.
Project saved.
Unable to load passage.

C. 圣经研究和篇章分析专业术语

D. Logical Relationships / proposition relationships

E. notation profile 相关术语

F. 帮助文档和较长说明文字

其中 C、D、E 属于高风险翻译内容。

特别是以下类型的术语，不允许直接依赖机器翻译后自动定稿：

Ground
Inference
Action–Purpose
Action–Result
Conditional
Idea–Explanation
General–Specific
Fact–Interpretation
Concessive
Situation–Response
Series
Progression
Comparison
Question–Answer

以及源码中出现的其他所有 discourse analysis / bracketing 专业术语。

请为这些术语制作一份“术语审核表”，包含：

英文原文
当前缩写或符号（如果有）

备选译名（如有）
白话解释
出现位置
是否属于 BibleArc / Schreiner / Beale / Gurtner 等体系中的专用名称
你的推荐理由

专业关系名称原则上优先采用：

中文名称 + 英文原文

例如：

不要贸然把英文完全隐藏。

# 阶段 3：搭建 i18n 基础架构

只有在中文翻译规范确认以后才进入。

目标：

1. 建立正式 i18n 层。
2. English 作为完整基准语言。
3. 新增 zh-CN。
4. 不允许通过大量 if(language === ...) 分支实现。
5. HTML 静态文本应采用统一的数据标记或等价机制。
6. JavaScript 动态文本统一通过翻译函数。
7. 支持变量插值，例如：
   “Loaded 12 propositions”
   不能拼接出语序错误的中文。
8. 处理：
   - title
   - placeholder
   - tooltip
   - aria-label
   - confirmation dialogs
   - status messages
9. 语言设置保存到项目现有适当的持久化机制中。
10. 如果合理，支持：
   - Follow System
   - English
   - 简体中文

要求：

切换语言后尽量即时生效。

如果某个中文 key 缺失，应安全 fallback 到英文，不应显示 undefined 或直接报错。

完成后运行已有测试，并增加 i18n 相关基础测试。

阶段结束后给我《阶段 3 报告》，告诉我：
