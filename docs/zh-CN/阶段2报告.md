## 2. 发现了什么

**专业名称的差异必须保留。** 例如 Gurtner 的 Way-End 对应软件内部 action-manner；Gurtner／Beale 的 Means-End 对应 action-purpose；Adversative 对应 concessive。软件内部的对应关系，不表示这些英文名称或中文译名可以自动合并。

**软件原文也存在需要谨慎解读的地方。** Bilateral 的定义写的是“支持前一命题，同时受后一命题支持”；Double Ground 则写一个命题受到两侧理由支持。表中保留原文、分别解释，不用一般教材印象代替软件定义。Way-End 未获得单独定义，其 End 的译法列为重点待审。

**自带关系文档与当前软件存在符号差异。** Comparison、Both-And 等都有实例；审核表已同时列明文档位置和当前各 profile 的符号，以当前运行规则为软件事实，不修改任何符号或星号位置。

**一些看似普通的英文其实会进入用户数据。** Imported text、Anonymous、Custom 等不能直接在源码中换成中文；清单注明只处理能明确区分的数据外层显示。

**中文界面不等于所有输入已经支持中文。** 当前经文范围解析仍使用英文书卷名，云端记号方案名称的标准化也会去除中文。后者在独立测试环境中调用纯函数确认，没有连接云端。这里只记录限制，没有改变原命名协议。

## 3. 有没有风险或需要注意的问题

- 所有专业译名、定义中译、关键词释义和专业相关界面句子都标为待审核，没有自动定稿。
- 这是一轮静态提取与人工复核，不是已经运行完成的中文界面。自动菜单、系统对话框、第三方组件和运行时视觉覆盖仍需后续验证。
- 术语依据是当前源码及自带 DOCX；没有声称使用了各学者认可的官方中文术语，也没有补造学术出处。PDF 没有另行逐页核验。
- 原导入帮助有与当前编辑模式不一致的说法，清单已注明；本阶段没有擅自修改原文或功能。
- 资料中 809 条候选包括内部文字和模板片段；470 条进入界面文案清单。这个数量是可追踪的记录数，不等于未来翻译函数键数。

## 4. 有没有需要你决定的事情

需要你审核专业用语和呈现建议，工程实现方式不需要你决定。建议优先看翻译规范末尾的重点表，再按专业表 C／D 编号反馈：

- “括号分析”还是“括弧分析”；Block Diagram 是否采用“缩进结构图”。
- Notation profile 是否用“记号方案”；主次、主旨、主旨摘要是否清楚区分。
- Bilateral、Double Ground 和 Way-End 的建议名称及解释。
- Idea-Explanation、General-Specific、Fact-Interpretation 的分别译名。
- 保持 Concessive／Adversative、Action-Purpose／Means-End 等不同体系名称，以及关系全称优先双语显示的方式。

其余专业关系也需要你的确认。可以直接说“同意某条建议”或给替代名称；本轮不会把没有反馈的专业建议当成已批准。
