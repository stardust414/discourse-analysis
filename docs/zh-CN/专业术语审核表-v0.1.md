## 审核入口与重点

推荐先审核 C18（记号方案）、C19（主次）、C20–C21（主旨及摘要），以及下列 D 关系卡片；随后逐套看 92 条 profile 对应表。建议专业全称通常显示“中文 + English”，括号图内的缩写、星号及颜色原样保留。短菜单可用已审核简称，英文由首次说明或悬停补足。

需要特别确认：

- Bilateral 暂译“双向关系”，不能仅凭当前定义认定为“双向理由”；与 Double Ground 分开。
- Way-End 的 End 意义未被软件单独定义，暂拟“方式—结果”，备选与疑问在对应卡片中；不据此改写 Action-Manner 的定义。
- Concessive 暂译“让步”，Adversative 暂译“转折”；保持各 profile 的不同英文名称。
- Idea-Explanation、General-Specific、Fact-Interpretation 分别审核；保留软件已有显示别名，绝不合并存储 ID。
- Block Diagram 暂译“缩进结构图”，备选“方块图”。这是用语建议，不是产品行为变更。

## 显示别名与用户自定义内容

软件原有 `ALIASES` 仅在当前 profile 缺少某关系而包含其别名时，把 `general-specific`、`fact-interpretation` 显示为 `idea-explanation`。这只是已有显示规则，存储 ID 不变。翻译层不得扩大映射，也不得说三个概念已经被学术证明为同义。

用户自定义的名称、符号、云端 profile 名称、评论和经文原样保留。专业编辑框不得因为显示了中文建议就把中文自动保存成自定义覆盖值。内置人名、BibleArc 名称以及稳定 profile ID 保持。

更多含专业词的状态、按钮、帮助、错误和无障碍句子，见独立附录“专业相关界面文案-v0.1.md”；它们同样全部待审。
