# 阶段 3 报告：i18n 国际化基础架构

完成日期：2026-11-03。固定上游基线为 Discourse Analysis 3.3.1，提交 `98da0241c38eef936be0f06cf736aa607dda0b62`。沿用分支 `codex/zh-cn-i18n`；专业关系显示依据已审核的 v1.0 材料。

**结论：阶段 3 已完成。三种语言选择、即时切换、本机保存、英文回退、专业关系独立显示和中英文搜索均已接通，并通过下列回归与桌面验证。建议进入阶段 4，但本次到此暂停，等待人工确认。** 这仍是代表性中文界面测试版，没有完成全软件中文化。

## 1. 语言系统现在怎样工作？

增加了一个轻量的显示层，没有引入新的国际化框架或运行依赖。English 是新接入文案的完整基准，简体中文字典只决定显示。中文缺项时显示英文；两种字典都缺项时显示非空的安全提示，不显示 undefined 或空白按钮。

HTML 中明确标记的文字统一翻译，涵盖正文、提示、占位、无障碍名称和 data-placeholder。没有对整页英文做全文替换，也不改 SVG、ID、快捷键和输入内容。动态文字使用完整句子模板，支持变量和数量表达；变量作为纯文字处理，不能执行 HTML。技术错误详情保留。

关系显示另有独立适配层：读取原始名称，再按当前 profile 显示审定的“中文 + English”。业务数据仍使用原来的 ID 和英文名称。开发接入方法见 [维护说明](../i18n.md)。

## 2. English、简体中文、跟随系统是否都可用？

都可用。设置中新增“界面语言 / Interface language”，提供三个选项，首次默认为“跟随系统”。

- English：显示英文。
- 简体中文：对已接入的文字显示中文，其余保留英文。
- 跟随系统：按系统首选语言判断；简体中文 Hans、CN、SG、MY 和普通 zh 使用简体中文，繁体及其他未支持语言回退 English。浏览器使用其语言设置，Electron 通过只读接口读取 macOS 系统语言。

本机实际系统首选语言是 `zh-Hans-CN`，桌面首次启动正确选择了简体中文。返回“跟随系统”时会重新读取系统设置。

## 3. 哪些代表性界面已经中文化？

已覆盖顶部若干工具按钮、Settings、语言设置、载入经文状态及错误、带变量的状态、清除确认消息、输入占位、tooltip、ARIA label、关系选择器、关系指南、当前记号方案提示、导出菜单和评论模板。详见 [代表性接入清单](阶段3代表性接入清单.md)。

五套内置 profile 的相关关系名称均按各自英文名称显示，没有把 Way-End、Means-End、Action-Manner 或不同 profile 强行合并。保留全部原有缩写、符号、星号、主次规则、颜色、顺序和映射。Way-End、Bilateral、Double Ground 等的中文帮助遵守人工审核决定。高级记号方案编辑器的可写名称输入框保留原文，避免把显示译名保存进用户方案。

新增字典含 125 个英文 key、118 个中文 key。这不是对原提取清单 470 条文案的完成率；7 个 key 有意使用英文回退，详见第 12 节。

## 4. 是否真正实现即时切换？

是。切换直接更新已接入的界面、打开的关系选择器、关系指南及仍可见的翻译状态，不刷新页面、不重新载入经文，也不调用整份项目重绘来实现翻译。

测试验证了评论草稿与光标、主旨摘要的选区、记号方案草稿、当前关系选择器搜索内容和用户自定义名称保持。评论正文、摘要、经文和其他用户内容不参与翻译。

## 5. 重启后是否保留语言选择？

是。选择保存在当前应用本机的 localStorage，键为 `biblebracket_language`。已验证 English、简体中文设置后关闭并重启，选择仍保留。它不写入项目 JSON、云端项目或撤销／重做历史。

## 6. 中文关系搜索是否可用？

可用。“理由”能找到 Ground，英文 Ground、缩写 Ac/Pur 和既有关键词仍正常。搜索还保留 profile 中的不同英文名称，并增加审定中文名称和相关说明。处理中文输入法组合输入，组合期间不会因回车误选关系，完成输入后再筛选。

## 7. 是否修改项目数据格式？

没有。项目 JSON 仍使用原版 version=3，没有新增语言字段。没有改变 relationship ID、profile ID 或 profile 数据结构。自定义 profile、自定义关系及被用户改过的内置名称保持原样，不写回中文译名。

同一测试项目已实际完成 **English 保存 JSON → 简体中文打开 → 切回 English**，核对经文、propositions、brackets、relationship IDs、comments、main point summary、parallel column 一致；当前 profile 也保持一致。profile 继续使用原版的本机偏好机制，没有为了此次验证增加项目字段。另验证语言切换不增加撤销记录或改变云状态。

## 8. 原有 English 模式是否退化？

在本轮验证范围内没有发现退化。原有 30 个 E2E 明确运行在 English，原断言保留，仅增加英文偏好的测试初始化；没有删除或弱化原测试。关系英文显示及原始名称仍保持原版结果。

没有升级 Electron、Node 依赖或其他上游组件。`package.json`、锁文件、核心编辑、保存、云同步、导出、绘图标签及记号编辑等 12 个核对文件与固定基线逐字节一致。关系搜索文件只扩展搜索和显示接入，五套内置 profile 的定义未修改。

## 12. 目前发现了哪些问题？

**原版两个已知状态保持不变：** 词内拆分后合并会插入空格；Mac 构建仍没有有效 Developer ID 签名。本轮未修复二者，也不把本机可启动等同于已签名、公证或通过下载后 Gatekeeper 验证。

**阶段范围内的限制：** 全面中文化仍待阶段 4。5 个尚未逐项审定的关系分组标题和两个云同步开关标签使用英文回退，未擅自把原材料中建议状态的术语提升为定稿。原生确认框的确认／取消按钮由系统控制；原生应用菜单及未标记文案仍显示原版文字。代表性中文界面未发现妨碍基本使用的布局问题，更全面的长文本布局优化留待阶段 5。

**验证脚本曾有三处问题，均已保留初次记录：** 新 E2E 对零宽 SVG 的点击不稳定，改为应用原有键盘激活方式；自用桌面脚本把运行时 undefined 属性与保存后省略的属性直接比较，改为按实际项目 JSON 比较；重启后未等待欢迎页完成加载便操作设置，补足等待。没有因此改动上游业务代码或弱化原有测试。修正检查方法后，最终完整 E2E 和桌面检查通过。

原始日志、初次检查记录、最终结果、源码一致性、产物哈希和截图见 [阶段 3 验证证据](阶段3验证证据/)。本轮没有验证真实云端多人协作、Windows 运行或软件全部未覆盖路径，不能据此声称不存在任何缺陷。
