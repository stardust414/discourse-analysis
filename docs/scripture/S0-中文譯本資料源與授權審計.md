## 3. fetch(bible)：重點結果

[F1] https://fetch.bible/access/ ：官方是 static CDN，全卷請求；無自身使用限制，逐譯本 license 仍適用；允許長期 cache / fully offline 的文字須與逐譯本限制一起讀。metadata 提供 attribution 與 license filtering。不是動態 passage API。

[F2] https://fetch.bible/access/manual/ ：manifest `https://v1.fetch.bible/manifest.json`；四種格式：`/bibles/{id}/txt/{book}.json`、`html/{book}.json`、`usx/{book}.usx`、`usfm/{book}.usfm`。book IDs 為 lowercase USX book code。txt 不是單字串，`contents[chapter][verse]` 是 string / heading / note parts；只選 string 才是分析正文。HTML 不直接寫 editor。

[F3] https://fetch.bible/access/client/ ：`@gracious.tech/fetch-client`，FetchClient → fetch_collection → bibles.fetch_book；可 browser / Node、bundled IIFE；官方稱 zero external dependencies。沒有必要為本項目引入 bundler / 整套 reader CSS。

[F4] https://github.com/gracious-tech/fetch_collection ，本次 git 只讀審計固定 commit `c45928a5d8ddfea0c695f91306f7236f840d859a`（main）。對應 metadata permalink：

- https://github.com/gracious-tech/fetch_collection/blob/c45928a5d8ddfea0c695f91306f7236f840d859a/bibles/cmn_cus/meta.json
- https://github.com/gracious-tech/fetch_collection/blob/c45928a5d8ddfea0c695f91306f7236f840d859a/bibles/cmn_cut/meta.json

實際 `ids.ebible` 分別是 cmn-cu89s / cmn-cu89t；source.service=ebible、format=usfm、revision=0、source.updated 分別 2021-10-15 / 2024-12-30。license=`public`、attribution=`public domain`。兩份 `year:1889` 與 USFM 1989 title 不符，需向來源確認，不能拿 1889 當版權起始年。source zip 可 pin SHA-256，但 CDN 仍是 mutable URL，S2 要記錄 response hash / converter version。

collection Mandarin tree 有 `cmn_bib/bibs/csbs/csbt/cus/cut/cuvmps/cuvmpt/feb/wcb`，未見 CNV / TCV。`cmn_bib` 是 Open Chinese Contemporary Bible，不是 CNV；`cmn_cuvmps/t` 是 2011 Modern Punctuation、CC-BY-NC-ND，不等於本項目的 CUVS/T。不能拿它們替換。

[F5] https://fetch.bible/access/collections/ ：可 self-host / custom collection，取得 restricted translation 授權後再放自有 collection；工具 license 不授予經文權利。上游優先不自託管版權全文。

[F6] https://github.com/gracious-tech/fetch/tree/master/converters/usx-to-json ：txt format 分離 heading/note objects，HTML 有自訂 classes。採用小 adapter 可降低 coupling，但不能簡化成 `contents[ch][v].join('')`。

官方說發行格式採統一 KJV numbering，raw original source 可從 collection 取得；章節重編、LXX 某段被省略的 policy 也有說明。因此不應把既有 Greek/Hebrew 全遷至此服務。實際檢驗又見下面 3 John 發行格式保留 15，文件的總體說明不能替代每版實測。

## 4. 簡繁資料複核：原始 source 與 CDN 不能混為一談

Cloud 對 eBible 直接下載被策略阻擋。本次從 **fetch 官方 collection 的 eBible source.zip 鏡像**各別計算，不是讀舊 local-cuv，也不是聲稱直連取得 eBible 最新 ZIP。複核來源：[F4] 上述固定 commit 下 `bibles/cmn_cus/source.zip`、`bibles/cmn_cut/source.zip`。沒有將全文存入本專案 Git。

| 計數口徑 | cmn_cus 的 eBible source.zip | cmn_cut 的 eBible source.zip |
| --- | --- | --- |
| .usfm 正典書卷 | 66 | 66 |
| `\c` markers | 1189 | 1189 |
| `\v` markers / body records | 31,021 | 31,021 |
| range verse labels | 70 | 70 |
| 章內 1..max span 展開後缺號 | 11 | 11 |
| PSA 119 records | 176 | 176 |
| 3JN 1 records / 最後 marker | 15 / 15 | 15 / 15 |
| ZIP SHA-256 | b563d7c001aca8d4157aaac4878890bd97c30a4f4bf9ffe155fbfb836c381bbf | a6f2ba7474ba43a79e11dbdb5cdf013626d03101f28c0bb367fec7e6a2e834e0 |

70 個 range label 的 book/chapter/ref 序列兩者相同；此處只證明結構一致，**不證明正文只是簡繁轉換**。簡體神、繁體上帝已是實際差異。

兩者缺號均為 MAT 18:11、23:14；MRK 7:16、15:28；LUK 17:36、23:17；JHN 5:4；ACT 8:37、15:34、24:7、28:29。這是章內缺節，不是拿 KJV 全本 verse count 相減。計算將 29-30 覆蓋 29、30，但仍只算一條 record；不把 footnote 算 body。

可重現方法：固定 [F4] commit，讀各 source.zip 的 66 個 `.usfm`；以 `\id` 識別書卷，按 `\c <chapter>` 分段，讀 `\v <number or range>`，逐章展開 span 僅作 coverage 計數；不要解析 footnote 中的引用為新節。這是 USFM marker 結構統計，未聲稱完整語義 / 異體字校勘。現行 eBible 直連 ZIP 的 byte-identical 核驗仍是後續 gate。

額外現場 sample：

- https://ebible.org/cmn-cu89s/3JN01.htm 及 https://ebible.org/cmn-cu89t/3JN01.htm ：各自確實標 1:15，note 1:7 另列。
- https://v1.fetch.bible/bibles/cmn_cus/txt/3jn.json 與 cmn_cut 對應路徑：兩者 contents[1] 保留 verse 15；notes 是 objects。
- https://v1.fetch.bible/bibles/cmn_cus/txt/gen.json ：創24:29 放整段合節正文，24:30 為 `[]`。僅請求 30 若機械 index，會誤認缺節。
- https://v1.fetch.bible/bibles/cmn_cut/usx/gen.usx ：保留 `number="29-30" sid="GEN 24:29-30"`。
- https://v1.fetch.bible/bibles/cmn_cus/usx/3jn.usx 及 cmn_cut 對應檔：`sid="3JN 1:15"`。

metadata 本身不含 31,021 等統計，不能只憑 metadata 重述舊數字。以上是新讀公開 source 的計算；S2 還需對選定發行格式作全本 parity，尤須 superscription、Psalm numbering 和 span lookup，不能以這次 source count 充當 CDN parser 驗收。

## 5. FHL

[L1] https://bible.fhl.net/api/ 官方公開 JSON API，首頁直接警告：部分譯本僅授權給信望愛，請勿任意使用。第三方介面公開不等於全部譯本可轉授權。

[L2] https://www.fhl.net/main/fhl/fhl8.html ：FHL unv 是義工輸入並加註 / 改地名的 FHL 和合本，採 GNU FDL 1.1 or later，頁面明確說與聖經公會新標點版至少 2203 處不同。`unv` 不是目標 CUNP 的合法同義替代。CNV 列 WBS 版權；TCV95 / TCV2019 列 ©UBS，FHL 透過台灣聖經公會獲授權。此許可未證明延伸到本 app。

[L3] https://bible.fhl.net/json/abv.php?gb=0 本次 metadata：`unv` candownload=1；`ncv`（新譯本）、`tcv95`、`tcv2019` candownload=0。沒有獨立 eBible cmn-cu89s/t 身份。`gb=0/1` 是服務輸出繁簡選擇，不能當成出版社批准的另一 edition。

schema：`/json/qb.php?bid=...&chap=...&sec=...&version=...&gb=0`；status / record_count / version / v_name / record，record 有 bid、engs、chineses、chap、sec、bible_text。sec 可單節 / 範圍 / 列表；book numeric ID 與英縮寫來自 `/api/listall.html`，不能沿用 Bolls 假設。notes 另有 rt.php。abv.version 可當更新信號而非內容 hash。

沒有在已讀文檔找到數值 rate limit、第三方 cache TTL、CNV/TCV 全本離線允許或通用 CORS 承諾。CORS 實測被 Cloud 403 擋住，記 unknown。對 CNV/TCV 的 span、Psalm、3 John source schema 未批量抓取，不能聲稱已驗證其與 eBible 一致。

結論：對版權目標 **third-party application permission not established**。S2 不推薦 FHL 作預設 provider；若未來另用 FHL unv，須獨立 edition label / GFDL 合規及明確 API 使用條件，不能冒稱 CUNP。

[P5] https://api.bible/api-key-guide ：需要 API key；既有本專案已為 NASB 整合 API.Bible，但不表示中文授權或 key quota 已準備。新共享 key 留 Firebase / 其他 server proxy、secret manager、配額與濫用防護；不放 renderer，也不把共享 secret 當成可安全藏於 app.asar。用既有 main IPC 只隔離 renderer，不能防包內 secret 提取。永久 offline 需特別合約，預設不支持。

API.Bible book/chapter/passage IDs 是 USFM 類 `GEN.1.1`、span range；回傳完整 grouped span 需保留實際 reference。各 CNV/TCV Psalm/3 John 差異必須在獲取確切 ID 後取少量 sample 驗證，目前 unknown。

## 8. Cloud、CORS、版本與剩餘問題

實際 Cloud urllib GET（帶 `Origin:http://localhost:8766`）到 `v1.fetch.bible/manifest.json`、eBible 簡體 USFX ZIP、FHL abv 均在 tunnel 階段 `403 Forbidden`。沒有 origin response，不能判定 provider CORS 拒絕或成功；GET / HEAD / OPTIONS 要在網路 policy 正式允許後重驗，不能繞代理。Firecrawl 可讀網頁不代表 Cloud runtime 可用。

GitHub 的官方 collection git clone 成功，僅讀 metadata、tree 與 CUV source blobs；未 checkout 其他版權譯本、不取私有分支、不改主專案依賴。Cloud Chromium/UI 還有 CSP 與 file:// Origin:null 的額外 gate。registry 只能顯示「設計候選」，不宣稱已完成 Electron runtime 整合。

發布前 blocker：A/B exact edition / rights 澄清；選定 raw vs normalized 格式及 spans 全本 parity；Cloud 域名正式開通與 CORS/CSP smoke。C/D 額外需要版權方批准 online、cache、project 永久保存/編輯/分享、全文 offline、商業範圍、attribution、更新/撤回條件和可用交付格式。這些不妨礙 docs S0 或保持既有行為的 S1，但會阻止相應譯本對外發布。
