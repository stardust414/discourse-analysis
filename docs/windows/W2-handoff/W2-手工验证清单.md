# W2 手工验证清单

每项记录测试环境、操作、实际结果和截图／文件。当前模板全部未验证。先读 README-W2.md，核对 EXE 哈希并正常双击，安全拦截只记录，不关闭保护。

## 环境与启动

- 记录 Windows 名称、版本、build，物理 PC／虚拟机，ARM64／Intel／AMD x64；ARM 的 x64 模拟结果单独归类。
- 正常双击 EXE：启动、错误、可操作耗时、图标、任务栏图标、最大化、最小化、关闭和再启动。不要把 PE 资源版本当作 `app.getVersion()`；后者单独记为已采集或未验证。
- 记录临时解压位置、确认过的 userData 路径；可用收集器记录候选目录，但没有 `app.getPath` 或充分证据时不要把猜测写成确认值。重启验证语言、profile、localStorage 偏好保持。

## 三种语言和菜单

- 设置中分别选 English、简体中文、Follow System；语言切换即时，当前项目／评论／摘要／个人方案名称不变。
- 简体中文系统首选语言：Follow System → zh-CN；非中文系统：Follow System → English。没有对应语言环境时保留未验证，不安装语言包凑结果。
- 分别拍中英文 File／Edit／View／Help；检查 role 对应动作及 accelerator，不能有 Cmd-only 组合或 Mac 专属菜单结构。未提供的上游菜单项不要凭空补一项。

## Ctrl 与焦点

- 在正文、搜索框、评论、摘要、关系搜索框分别验证适用的 Ctrl+A／C／V。
- 在分析工作区验证 Ctrl+S、Ctrl+Z、Ctrl+Y、Ctrl+Shift+Z；在文字编辑中同时核对字段本身与项目撤销的边界，不强行把所有键都解释成项目撤销。
- 打开／关闭菜单和弹窗，记录 Tab、Enter、Esc 与返回焦点。原版没有应用级 Ctrl+O，使用按钮打开即可。

## 微软拼音 IME

如果已安装微软拼音，用真实键盘输入，不用 DevTools 派发 composition 事件。

1. 关系搜索分别输入“理由”“推论”“行动”。记录拼音输入、候选窗、确认词、Backspace、焦点。
2. 候选阶段按 Enter：只能确认输入法内容，不能提前选中关系。组合结束后才能正常选择关系。
3. 在命题文字中输入中文；候选阶段 Enter 不应拆分 proposition。候选确认结束，再在普通分析状态按 Enter，应执行原应用的拆分行为。文字编辑模式的换行按该模式既有逻辑记录。
4. 候选窗截图仅含测试文字，裁去账号、个人词库或通知。没有微软拼音时标记未验证，不能以英文键盘或模拟事件替代。

## 字体、主题、DPI

- 中文无方框、字形及行高正常。检查 selector／Guide 的完整双语和原简称；五套方案切换后不应错位或改写记号。
- 真实载入 Greek（John 1:1–5，SBLGNT）、Hebrew（Genesis 1:1–3，WLC），记录 RTL、标点、选区及编辑。网络载入失败与字体问题分开记录。
- Light／Dark 各看输入、下拉、selector、modal、sidebar、原生菜单、disabled、placeholder 和 focus ring。系统主题自动跟随不是新增要求。
- **Windows Display Scale 100／125／150%** 每档分别测试约 800×600、默认、最大化。记录系统设置，应用 zoom 先固定 100%。每格查看工具栏、侧栏、选择器、Guide、Settings、评论、摘要、Block Diagram、Parallel Column、长双语名；记录合理滚动、截断、重叠和不可操作控件。

## 文件和保留名

- 使用普通英文 Documents 路径以及 `Documents\圣经 分析测试`。记录实际导出落点；如果默认进 Downloads，不能把后来移动文件后的打开测试说成“已直接保存到中文目录”。
- JSON 保存，关闭应用，再用应用按钮打开，逐项比较数据。如果 Windows 没有现成文件关联，双击 JSON 记为“不适用／未建立关联”，不为本阶段创建关联。
- 自动名不得包含 `: ? * < > | " / \`；测试自定义 CON、正常长文件名及中文名。超长路径报错原样记录，不改系统长路径策略。
- 分别导出 PNG／PDF，实际打开检查中文和原文，再由应用从图片／PDF 恢复，另存 JSON 与参考数据比较。
- 导入 `reserved-CON.daprofile.json`，确认界面名 CON；导出得到合法文件名，重新导入后名称、ID、关系、缩写一致。完成后切回旧项目所用 Gurtner。
- 如现有环境允许，再验 OneDrive／UNC；没有现成目录时标记未验证，不连接未知共享。
- 检查小写 `.json` 和大写 `.JSON`：先测试应用“打开”按钮；在已正常启动且无安全拦截的前提下，可测现有命令行打开。大写命令行边界单独记录，不能误说所有普通打开都失败。

## 实际工作流与网络

分别用 `John 1:1-5` 和 `1 Cor 10:1-13` 完成：载入、Enter 拆分、合并、多个关系、五套 profile、中／英文／简称搜索、Guide、评论、摘要、Block Diagram、平行译本。

合并保留原版词内可能补空格的已知行为，不能把它当 W2 新 bug 顺手修复。

ESV／NASB 分别作代表性载入，Greek 用 NT 引用，Hebrew 用 OT 引用。记录实际来源／fallback、时间、失败提示。外部 API／地区网络不可用不能直接判定 Windows bug，不修改网络策略或添加私有 API key 作为测试捷径。

## Mac 兼容与收尾

- 先用 Mac 冻结实际保存项目样例，在 Windows Gurtner 下打开，核对经文、命题、括号、评论、摘要、平行栏、作者、方向及导出。
- Windows 另存后比较 JSON，profile 独立比较；记录 schema 仍为 3、方案 schemaVersion 仍为 1，不能增加语言字段。
- 把 Windows 结果交回 Mac 冻结版反向打开；未执行就保留未验证。
- 保存填写的 CSV、截图、比较 JSON。Windows ARM 通过结果与原生 x64 PC 通过结果分开；没有 PC 时记录“W3 前仍建议 native x64 final smoke”。
