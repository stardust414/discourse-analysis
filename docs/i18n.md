# Internationalization (phase 5 polished UI)

The app still uses classic browser scripts. No runtime package or frontend build
step was added. English is the complete baseline for all introduced message keys;
the reviewed UI copy is now connected, including native menus, recovery, help and accessibility. All five relationship group headings are now approved and translated under v1.1.

## Files and boundaries

- `js/i18n/en.js`, `zh-CN.js`: flat message catalogs; strings or plural forms.
- `js/i18n/i18n.js`: locale resolution, local preference, safe interpolation,
  marked DOM bindings, templates, derived display bindings and change subscriptions.
- `js/i18n/relationships.js`: display/search adapter for the approved v1.0/v1.1 terms.
  `DA_PROFILES.getName()` continues to return the original data name.

The preference `biblebracket_language` stores `system`, `en`, or `zh-CN` in local
storage. It is not a document property, undo action or cloud setting. Electron
exposes only a read-only system-language query through its existing preload bridge.
The primary system locale is used: Hans/CN/SG/MY and plain `zh` select Simplified
Chinese; Hant and unsupported locales fall back to English. Browser language is
used if the native query is unavailable. Returning to `system` queries the OS again.

## Using messages

```js
DA_I18N.t('project.codeCopied', { code }); // plain text, never HTML
DA_UI.showTranslatedStatus('relationship.removed', { count }, 'success');
// A derived display value must also be resolved again when locale changes:
DA_UI.showTranslatedStatus('relationship.changed', () => ({
  label: DA_RELATIONSHIPS.getName(type)
}), 'success');
```

English plural messages use `{ one: '...', other: '...' }`. Chinese can use a
single complete sentence. Plural rules follow the actual fallback message's locale.
A missing Chinese entry falls back to English; a missing English entry returns the
non-empty safe text `Text unavailable`. Add an English entry for every new key.

```html
<button data-i18n-title="settings.tooltip">
  <svg><!-- existing icon --></svg>
  <span data-i18n="settings.open">Settings</span>
</button>
<input data-i18n-placeholder="passage.placeholder">
```

Supported markers: `data-i18n`, `data-i18n-title`, `data-i18n-placeholder`,
`data-i18n-aria-label`, `data-i18n-data-placeholder`, and `data-i18n-data-drop-label`
(the last supplies CSS-generated drop instructions). Fixed parameters can use
`data-i18n-args` containing JSON. Prefer a marked text span when a control contains
icons or keyboard hints. Only explicit bindings are translated. Input values and
editable content are never replaced by text bindings.

`DA_I18N.apply(root)` supports DOM fragments, template contents and cloned
elements. A child-list observer applies bindings to newly inserted elements; it
does not inspect or replace arbitrary text. Live parameter providers use weak
references to DOM elements. `onChange()` returns an unsubscribe function.

## Relationship safety

Only recognized, unchanged builtin names are localized. Custom profiles, renamed
relationships and `cl_` labels remain verbatim. Profile IDs, type IDs, aliases,
abbreviations, stars, colors and ordering are not translated. Do not use the
display adapter to populate the notation editor's writable name inputs.

Search extends the existing index with approved Chinese names and help text while
preserving all original English names, abbreviations and keywords. Filtering waits
for IME composition to finish; Enter during composition does not select a result.

Chinese help for Bilateral and Way-End follows the human-reviewed v1.0 decisions.
The original English definitions remain unchanged as upstream baseline evidence.
All group headings have approved Chinese under v1.1. The two cloud
toggle labels were confirmed approved in the v1.0 ordinary UI list and now translate.
Original data defaults, names, symbols and technical details remain verbatim.

## Regression checks

`npm run check` runs lint, type checks and all unit tests. `npm run test:e2e` runs
the original 30 English scenarios plus the new i18n scenarios. The original tests
explicitly seed English; their assertions are preserved. Native Mac validation
uses a separate `--user-data-dir` and the actual ZIP-extracted application.

Do not fix the original word-internal split/merge spacing behavior or change the
signing strategy as part of internationalization. See the Chinese phase 5 report
for current results, artifact locations and remaining limitations.


## Completing and auditing coverage

`DA_I18N.bindValue(element, () => displayText, attribute = 'text')` binds a
locale-sensitive derived label or date, including title, placeholder and ARIA.
It never writes form values or innerHTML. Return plain text; keep user values
verbatim. The same node remains mounted, preserving drafts and selections.

`s.S####` keys retain the stage 2 source-record ID. Consolidated fragments use a
complete named template instead. `docs/zh-CN/阶段4覆盖映射.json` accounts for all
470 source records: 462 connected and 8 explicitly preserved data defaults,
technical details or translation names. This is record accounting, not a promise
that every character on screen is Chinese. Relationship matrix coverage is
separate from these source records.

Run `node scripts/audit-i18n.cjs` for key validation and source-inventory review.
The guard is also exercised by `npm run check`. It checks all introduced approved
Chinese keys and flags newly added or increased source literals across renderer,
main process, API proxy, HTML and CSS. The source snapshot is a review trigger;
it cannot infer whether arbitrary code or user data is visible UI. Review new
text against the residual-English audit before running `--write-snapshot`.
Do not regenerate the snapshot merely to bypass a failing check.

Native menus reuse the original Electron menu roles, structure and accelerators.
The renderer sends only a whitelisted resolved locale through preload; the main
process checks the sender and translates labels from the same catalogs.
OS-owned Services, file pickers, About metadata and third-party errors may still
use system or technical language. No dependency or system-language setting is
changed. See `docs/zh-CN/残留英文审计.md` for the explicit A–F and twelve-category
review decisions, and the phase 5 report for validation limits.


## Compact relationship presentation (v1.1)

`DA_RELATIONSHIPS.selectorPresentation(type)` returns display-only `{ compact,
name, abbr, full }`. Chinese builtin choices use separate name and abbreviation
spans. The abbreviation is the exact active `getAbbr()` value, including case,
spaces, slashes and stars. Never write this presentation object into a profile.
Custom/renamed profiles and labels keep their original names. English retains its
existing full labels.

The picker uses container queries: at default width both parts remain visible;
constrained width compresses Chinese; extreme width hides Chinese visually and
retains the complete abbreviation. The full bilingual name remains the accessible
name, title and hover/focus detail. A focus event supplies the same detail as
hover. Test the shipped Electron engine as well as Chromium.

Current source snapshot: `docs/zh-CN/阶段5源码文本审计.json`. There are no deliberate
missing Chinese production keys; missing-language fallback tests create an empty
Chinese catalog in an isolated sandbox. Screenshots use settled layout and disabled
finite capture animations, not CSS zoom. Layout cases call the existing app zoom
function at its actual supported levels. The import-status Enter correction is an
authorized upstream copy fix, not a change to splitting behavior.
